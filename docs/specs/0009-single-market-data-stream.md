# SPEC-0009: Одно стрим-соединение на все инструменты

**Статус:** Готово (ждёт перезапуска сервиса) · **Обновлено:** 2026-10-13 · **Зависит от:** SPEC-0002

## Зачем

Лимит T-Invest (официальная документация `limits.md`): **16 активных
stream-соединений сервиса котировок** на грейдах 1–4, 64 — на грейде 5.
Внутри одного соединения — до 300 подписок (сделки, стаканы, свечи
суммарно). Счётчик соединений обновляется раз в 2 минуты. Документация
советует не занимать лимит полностью: одно соединение нужно для
переподключения.

ClusterSource открывает **отдельное соединение на каждый инструмент** (~59),
и каждое со своим `AsyncClient`. Это в 3,7 раза больше лимита.

Факты из лога после перезапуска 2026-10-12 20:44 МСК (до 07:22 МСК 2026-10-13):

| Что | Сколько |
|-----|---------|
| Открытий стрима | 883 |
| Обрывов стрима | 851 |
| `RST_STREAM with error code 8` (сервер сбрасывает соединение) | 1 378 |
| Ошибок `FindInstrument` / `Futures` (резолюция FIGI при каждом переподключении) | 3 767 / 1 582 |
| Заголовок ответа | `ratelimit_limit='600, 600;w=60'` |

Сервер сбрасывает соединения сверх лимита. Коллекторы переподключаются по
кругу: каждый раз новый клиент, новая резолюция FIGI, новый запрос DNS.
Так стрим инструмента живёт минуты, а между жизнями сделки теряются. Это
объясняет и неполноту прошлых дней (SPEC-0001: от 57 до 99% сделок в
обычные дни) — ни один день не помечался неполным.

## Делаем / Не делаем

**Делаем:**
- одно соединение `MarketDataStream` и один `AsyncClient` на процесс;
  все подписки на сделки (`TRADE_SOURCE_EXCHANGE`) — в нём;
- FIGI всех инструментов разрешаются один раз до открытия соединения и
  заново — только при ролловере непрерывных фьючерсов;
- входящие сделки раздаются по инструментам (по `figi` / `instrument_uid`)
  в очереди существующих `DataCollector`: консьюмеры, пакетная запись и
  отметки дней не меняются;
- при обрыве — одно переподключение с экспоненциальной задержкой и
  повторная подписка всех инструментов; день отмечается `stream_gap` у всех
  инструментов, а не у одного;
- при старте — запрос тарифа (`GetUserTariff`) и запись в лог лимита
  соединений;
- проверка ответа на подписку: инструменты, подписка которых не
  подтверждена (`subscription_status` ≠ OK), — в лог и отметка `stream_gap`.

**Не делаем:**
- не меняем хранилище, консьюмер и формат тиков;
- стаканы и свечи — не в этой спецификации; в то же соединение потом
  добавятся торговые статусы (SPEC-0004) и ОИ (SPEC-0007).

## Гарантии

- **G-1.** Число одновременных stream-соединений сервиса котировок ДОЛЖНО
  быть не больше 1 (сделки). Будущие подписки добавляются в него же, пока
  их не больше 300.
- **G-2.** Переподключение ДОЛЖНО повторно подписывать все инструменты и
  отмечать `stream_gap` у всех.
- **G-3.** Инструмент, подписка которого не подтверждена сервером, НЕ ДОЛЖЕН
  молча считаться собираемым: предупреждение в логе (`STREAM_SUBSCRIPTION_FAILED`)
  и отметка дня.
- **G-4.** Резолюция FIGI НЕ ДОЛЖНА выполняться при каждом переподключении:
  только при старте и ролловере.

## Данные и контракты

- `docs/contracts/asyncapi/t-invest-market-data-stream.asyncapi.yaml`: одна
  подписка со списком инструментов (до 300), ответ `subscribe_trades_response`
  со статусами.
- Хранилище не меняется.

## Наблюдаемость

- Лог при старте: `Лимит stream-соединений котировок: N` (из тарифа).
- Число переподключений в час; список неподтверждённых подписок.

## Журнал решений

- **2026-10-13** — Причина обрывов стрима и неполноты данных найдена: превышение лимита соединений. Предложено одно соединение на процесс.
- **2026-10-13** — Согласовано и реализовано. `DataCollector` стал приёмником сделок (`deliver` + консьюмер), соединением и переподключением владеет `StreamHub`; ненайденный инструмент больше не останавливает коллектор, а не входит в подписку до следующей резолюции.
