# Спецификации задач

Каждая задача, меняющая поведение ClusterSource, начинается со спецификации в
этом каталоге. Спецификация — живой документ: после реализации она не
архивируется, а остаётся действующим описанием поведения.

## Правила

- Файл `NNNN-краткое-имя.md`, номер сквозной, не переиспользуется. Шаблон — [_template.md](_template.md).
- Статусы: **Черновик** → **Согласовано** → **В работе** → **Готово**; либо
  **Заменено SPEC-NNNN**. «Согласовано» ставит владелец продукта.
  «Готово» — только когда у каждого критерия приёмки есть тест.
- Гарантии нумеруются внутри спецификации: `G-1`, `G-2`, … Ссылка извне — `SPEC-0001 G-2`.
- Трассировка в коде: в месте реализации гарантии — комментарий `# SPEC-0001 G-2`,
  в тесте, который её проверяет, — тот же идентификатор в docstring.
  `grep -rn "SPEC-0001" src tests` показывает всё, что относится к спецификации.
- Решения и ответы на открытые вопросы записываются в «Журнал решений» с датой.
- Нормативные слова: **ДОЛЖЕН** / **НЕ ДОЛЖЕН** — обязательное требование;
  **СЛЕДУЕТ** — рекомендация, отступление объясняется в журнале решений.
- Время в спецификациях: UTC, если не указано «МСК».
