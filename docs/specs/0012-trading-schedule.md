# SPEC-0012: Расписание торгов

**Статус:** В работе — этап 1 (календарь ISS) · **Обновлено:** 2026-10-14 · **Зависит от:** SPEC-0003, 0008, 0011

## Зачем

Режимы торгов (утро / основная / вечер / выходные) задают нормы сигналов
(SPEC-0008), конец вечерней сессии — проверку среза ленты (SPEC-0011),
неторговые дни — ожидания сбора и сверки. Сейчас это постоянные границы в
конфигурации, и они уже оказались неверными: основная сессия акций была
задана с 10:00 по росту объёма, а по расписанию она с 09:00. Расписание
меняется (праздники, отменённые сессии выходного дня, переносы сессий),
поэтому его нужно получать, а не задавать.

### Исследование 2026-10-14

| Источник | Что даёт | История |
|----------|----------|---------|
| T-Invest `InstrumentsService/TradingSchedules` | Сессии, аукционы, клиринг по «расписанию» инструмента: акции — `moex_mrng_evng_e_wknd_dlr` (44), фьючерсы — `forts_futures_weekend` (8); всего 148 расписаний | Нет: `from` не раньше текущей даты (ошибка 30003) |
| ISS `/iss/engines/futures.json` → `session_schedule` | Сессии дня FORTS: утро 07:00–09:00, основная 09:00–19:00, вечер 19:00–23:50, клиринг 23:50 | Нет: параметр даты игнорируется; у акций блока нет |
| ISS `/iss/engines/{stock,futures}.json` → `timetable`, `dailytable` | Недельный шаблон (все 7 дней — торговые, с сессиями выходного дня) и исключения по датам с 2018 года: праздники, отменённые сессии выходного дня (15–16.08, 12–13.09.2026), рабочие дни в праздники | Да; времена — часы торговой системы, не сессий |
| Лента ISS (SPEC-0003): `TRADINGSESSION`, `PERIOD` сделок акций | Точные границы за день. 13.10 (TQBR): аукцион открытия 06:59, утро 07:00–08:59, основная 09:00–18:54, аукцион закрытия 18:57–18:59, вечер с 19:00 | Да, с 12.10; у FORTS метки сессии нет |

Все источники согласны: у акций и фьючерсов утро до 09:00, основная
09:00–19:00, вечерняя с 19:00. Отменённые сессии выходного дня из
`dailytable` совпадают с ответами архива T-Invest (404 за 15–16.08 и 12–13.09).

## Делаем / Не делаем

**Делаем (этап 1):**
- календарь торговых дней ISS обоих рынков: разовая загрузка всей истории
  `dailytable` и недельного шаблона `timetable`, далее обновление ночью;
- правило «торговый ли день» по календарю;
- исправление границ режимов по умолчанию (утро до 09:00 и у акций).

**Делаем (этап 2, отдельным согласованием):**
- ночная загрузка расписания T-Invest на 7 дней по расписаниям наших
  инструментов и `session_schedule` FORTS для сверки, хранение по датам
  (история копится сама);
- границы сессий акций за прошлые дни — по меткам ленты ISS;
- применение: режимы норм и детекторов по расписанию дня (нет дня —
  границы из конфигурации), аукционы отдельным режимом, конец вечерней
  сессии для среза ленты (SPEC-0011), неторговые дни.

**Не делаем:**
- платные источники расписания;
- восстановление времени сессий за дни до 12.10 — его нет ни в одном
  бесплатном источнике; для них — границы из конфигурации.

## Правила

**Торговый день рынка** — если дата есть в `dailytable`, решает её
`is_work_day`; иначе — `timetable` для дня недели (1 — понедельник … 7 —
воскресенье). Календарь не загружен — неизвестно (`None`). Календарь
обновляется в конце каждого обслуживания (при старте и ночью).

## Гарантии

- **G-1.** Календарь ДОЛЖЕН храниться по датам и не терять загруженную
  историю: повторная загрузка обновляет строки, но не удаляет даты, которых в
  ответе нет.
- **G-2.** Ошибка загрузки календаря НЕ ДОЛЖНА останавливать обслуживание и
  сбор: остаётся прежний календарь.

## Данные и контракты

SQLite ленты ISS (`_iss.sqlite3`, `IssTapeRepository`):

```sql
CREATE TABLE iss_calendar (
    market      TEXT NOT NULL,   -- shares | forts
    day         TEXT NOT NULL,   -- YYYY-MM-DD
    is_work_day INTEGER NOT NULL,
    start_time  TEXT,            -- часы торговой системы, МСК
    stop_time   TEXT,
    loaded_at   TEXT NOT NULL,
    PRIMARY KEY (market, day)
);
CREATE TABLE iss_week_timetable (
    market      TEXT NOT NULL,
    week_day    INTEGER NOT NULL, -- 1 — понедельник … 7 — воскресенье
    is_work_day INTEGER NOT NULL,
    start_time  TEXT,
    stop_time   TEXT,
    PRIMARY KEY (market, week_day)
);
```

ISS: `GET /iss/engines/{stock|futures}.json?iss.only=timetable,dailytable`
(`docs/contracts/openapi/moex-iss.openapi.yaml`, `getEngine`).

Чтение: `schedule.is_trading_day(iss_repo, market, day)`.
