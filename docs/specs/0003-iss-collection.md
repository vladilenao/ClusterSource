# SPEC-0003: Сбор ленты Мосбиржи из ISS

**Статус:** Готово (этап 2 работает с 2026-10-13; этап 1 отключён) · **Обновлено:** 2026-10-12 · **Зависит от:** —

## Зачем

Лента Мосбиржи — независимый от брокера источник для сверки (SPEC-0005) и
единственный источник двух полей:

- `TRADENO` — биржевой номер сделки;
- `OPENPOSITION` — открытый интерес после каждой сделки фьючерса (SPEC-0007).

Бесплатный ISS отдаёт сделки **только текущего торгового дня** с задержкой 15
минут (параметр `date` игнорируется). Сами сделки за пропущенный день потом
даст архив T-Invest, но `TRADENO` и `OPENPOSITION` за этот день теряются
безвозвратно. Поэтому ленту нужно забирать каждый день, начиная с 2026-10-12.

Факты (проверено 2026-10-12):

| Что | Значение |
|-----|----------|
| Лента всего рынка акций | `GET https://iss.moex.com/iss/engines/stock/markets/shares/trades.json` |
| Лента всего FORTS | `GET https://iss.moex.com/iss/engines/futures/markets/forts/trades.json` |
| Пагинация | Курсор: `tradeno=<номер>&next_trade=1` (акции), `recno=<RECNO>&next_trade=1` (FORTS), `limit` из 1/10/100/1000/5000 (иное значение — 1 строка). `start` в справочнике ISS помечен устаревшим: на глубоких смещениях ISS отвечает пустыми страницами — 2026-10-12 сервис застрял на 2 548 790 строке (акции, 16:29 МСК), этап 1 — на 2 748 450 (акции, 17:12) и 1 350 000 (FORTS, 12:41) |
| `previous_session=1` (FORTS) | Отдаёт только начало прошлой сессии (2026-10-13 для 10-12: до ~07:10 МСК); для восстановления дня непригоден |
| Доступность | весь текущий день с начала утренней сессии: запрос в 19:45 МСК вернул первую сделку 06:52 (акции) / 06:00 (FORTS) |
| Колонки, акции | `TRADENO, TRADETIME, SECID, PRICE, QUANTITY, PERIOD, VALUE, BOARDID, SYSTIME, BUYSELL, DECIMALS, TRADINGSESSION, TRADEDATE, TRADE_SESSION_DATE` |
| Колонки, FORTS | `TRADENO, BOARDNAME, SECID, TRADEDATE, TRADETIME, PRICE, QUANTITY, SYSTIME, RECNO, OPENPOSITION, OFFMARKETDEAL, BUYSELL, TRADE_SESSION_DATE` |
| Время | `TRADETIME` с точностью до секунды, МСК |
| `TRADENO`, акции | общая нумерация всего рынка: у SBER номера идут в среднем через ~35 |
| `TRADENO`, FORTS | в ленте не монотонен |
| Режимы торгов | в ленте акций все режимы (`TQBR`, `SMAL` и др.) |
| Неполные и пустые страницы | На глубоких `start` ISS отдаёт неполные и пустые страницы (10 пустых ответов подряд, затем полная). `reversed=1` игнорирует `limit` и не годится как признак конца ленты. С курсором `tradeno`/`recno` ответы полные (5000 строк за 0,3–0,6 с) |
| Скорость | ≈2 с на страницу из 5000 строк |
| Объём | в gzip ≈10 МБ на 800 тыс. строк; Parquet ≈1 МБ на 100 тыс. сделок; полный день — измерить по 2026-10-12 |
| Сессия выходного дня FORTS | Приходит пачкой в ленту понедельника: `TRADEDATE` — суббота/воскресенье (календарная дата сделки), `SYSTIME` — понедельник ~06:00 (время загрузки), `TRADE_SESSION_DATE` — понедельник (торговый день). Лента FORTS 2026-10-12: 282 923 сделки субботы, 292 576 — воскресенья |
| Дневные итоги | `/iss/history/engines/stock/markets/shares/boards/TQBR/securities.json?date=` и `/iss/history/engines/futures/markets/forts/securities.json?date=`: `SECID`, `NUMTRADES`, по 100 строк (`history.cursor`); 2026-10-09: 512 бумаг TQBR, 843 контракта FORTS; за текущий день и субботу пусто |

Сессии выходного дня Мосбиржи (сб/вс 09:50–19:00 МСК) входят в **следующий
торговый день**. В дневных итогах ISS суббота показывает 0, а понедельник
включает выходные (SBER 2026-10-05: 227 892 сделки).

## Делаем / Не делаем

**Делаем:**
- **Этап 1 (временно, работает с 2026-10-12 19:45 МСК):** сырой сборщик
  `scripts/iss_raw_dump.py` под launchd.
- **Этап 2 (реализован):** сборщик `iss.IssCollector` внутри ClusterSource
  как фоновая задача с DI. Нормализованные сделки хранятся через новый
  `IssTapeRepository`, сырые файлы этапа 1 импортируются туда же; проверка
  полноты по дневным итогам ISS.

**Не делаем:**
- платный доступ в реальном времени (решение 2026-10-12, SPEC-0001);
- опрос по каждому тикеру: общая лента рынка дешевле.

## Гарантии

- **G-1.** Лента ДОЛЖНА забираться за каждый торговый день, включая сессии
  выходного дня, пока ISS отдаёт этот день.
- **G-2.** Если день забран не полностью (лента переключилась раньше, чем
  сборщик догнал её), это ДОЛЖНО фиксироваться как безвозвратная потеря полей
  ISS за этот день (лог и отметка). Сверка этого дня (SPEC-0005) тогда
  невозможна, и минуты получают `GAP`.
- **G-3 (этап 2).** HTTPS-проверка всегда включена, через `_ssl_context()`
  (инвариант A10).
- **G-4 (этап 2).** Повторно загруженные строки не дублируются: ключ
  уникальности — (рынок, `SECID`, `TRADENO`).
- **G-5.** Полнота забранного дня ДОЛЖНА проверяться: число сделок ленты по
  каждой бумаге режима `TQBR` (акции) и `RFUD` (FORTS) за торговый день
  сверяется с дневными итогами ISS (`NUMTRADES`). Сверяются все бумаги
  режима, а не только инструменты ClusterSource: это строже и не стоит
  дополнительных запросов. Расхождение равносильно G-2.

## Этап 1: временный сборщик

| Что | Где |
|-----|-----|
| Скрипт | `scripts/iss_raw_dump.py` (только stdlib) |
| Агент launchd | `~/Library/LaunchAgents/local.clustersource.iss-raw-dump.plist`, `RunAtLoad` + `KeepAlive` |
| Интерпретатор | `/opt/anaconda3/bin/python3 -I` |
| Данные | `{data_dir}/history/_iss_raw/{YYYY-MM-DD}/{shares,forts}.csv.gz` (многочленный gzip, строки ISS как есть) |
| Прогресс | `{data_dir}/history/_iss_raw/state.json` |
| Лог | `{data_dir}/history/_iss_raw/iss_raw_dump.log` |

Как работает: раз в 60 с догоняет обе ленты страницами по 5000. Смена дня в
ISS определяется по смене первой сделки ленты, при этом в логе появляется
`ISS перешёл на новый день`. Дата каталога — дата `SYSTIME` первой сделки.
Каталог `_iss_raw` не мешает сервису: репозиторий читает только
`{storage}/*.parquet`.

Ограничения:
- Mac должен быть включён и не спать: во сне опрос стоит. После пробуждения
  сборщик догоняет ленту, если ISS ещё не переключился на следующий день.
- Падение между записью страницы и сохранением прогресса даёт дубли.
  Дедупликация — при загрузке на этапе 2 (G-4).

Управление:

```bash
launchctl print gui/$(id -u)/local.clustersource.iss-raw-dump
```

```bash
launchctl bootout gui/$(id -u)/local.clustersource.iss-raw-dump
```

## Этап 2: сборщик в сервисе

Модули: `iss.py` (`IssCollector`, `HttpIssClient`, `normalize_trades`,
`trade_time_utc`), `database.py` (`IssTapeRepository`). Запускается из
`main.amain`, если `iss.enabled` (по умолчанию да).

- **Догонка.** Раз в `iss.poll_interval_sec` (60 с) для каждого рынка: первая
  сделка ленты (`limit=1`), затем страницы по 5000 после курсора (`TRADENO`
  на акциях, `RECNO` на FORTS, `next_trade=1`). Каждая страница и курсор
  сохраняются в одной транзакции. Конец ленты — пустой ответ, подтверждённый
  ещё двумя запросами через 2 с; тогда лента помечается `caught_up`. Ложный
  конец ничего не теряет: следующий цикл продолжает с того же курсора.
- **Смена дня.** Первая сделка ленты сменилась — прежняя лента выгружается в
  `_iss/{market}/{feed_date}.parquet`. Если она не была `caught_up`, это
  `ISS_FEED_INCOMPLETE` и статус `feed = incomplete` (G-2): дочитать прошлый
  день из ISS нельзя.
- **Нормализация.** Дата сделки — из `SYSTIME`, если сделка записана вовремя
  (не раньше чем за час до записи и не позже 5 мин), иначе из `TRADEDATE`
  (пачка сессии выходного дня FORTS). Время МСК → UTC. Торговый день —
  `TRADE_SESSION_DATE`. `B`/`S` → `BUY`/`SELL`. Колонки — [03-data-model.md § 3.7](../03-data-model.md#37-лента-мосбиржи-iss).
- **Хранение.** Текущая лента — `_sqlite/_iss.sqlite3` с `UNIQUE(market,
  secid, tradeno)`; прошедшие — Parquet. Выгрузка частями, с проверкой
  числа строк; существующий Parquet дня сначала возвращается в SQLite, так
  что повторная выгрузка объединяет данные без дублей. Сохраняются все бумаги
  ленты.
- **Раз в час:** выгрузка лент, оставшихся в SQLite после падения; импорт
  сырых файлов этапа 1 (`{market}*.csv.gz`) за дни, которые сборщик уже
  сменил более новой лентой; повторно — если файл вырос (флаг
  `raw_imported:{market}:{date}:{файл}` хранит размер; обрезанный файл →
  `feed = incomplete`);
  сверка торговых дней не старше 10 суток с `NUMTRADES` не раньше 06:00 МСК
  следующих суток (G-5). Нет итогов 3 суток — `unverifiable`.
- **Переход с этапа 1** — [10-operations.md § 10.4.1](../10-operations.md#1041-переход-с-временного-сборщика-iss-spec-0003-этап-1).

Проверено на реальных данных 2026-10-12 (2,75 млн строк обоих рынков): дата
времени каждой сделки совпала с `TRADEDATE`, все строки получили торговый
день 2026-10-12, выгрузка 300 тыс. строк в Parquet — около 1 с.

## Наблюдаемость

- Лог: `ISS X D: +N сделок, курсор K`, прогресс догонки каждые 100 тыс.
  строк, `ISS X: новая лента за D`, `ISS_FEED_INCOMPLETE`,
  `ISS_DAY_VERIFIED`, `ISS_DAY_INCOMPLETE` (с худшими расхождениями),
  повторы запросов.
- Таблица `iss_day_status`: полнота каждой ленты и каждого торгового дня.
