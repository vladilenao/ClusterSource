# SPEC-0004: Детекторы деградации данных

**Статус:** Готово (ждёт перезапуска сервиса) · **Обновлено:** 2026-10-13 · **Зависит от:** SPEC-0001, SPEC-0009

## Зачем

Сверка с ISS (SPEC-0005) выносит вердикт через 15–20 минут. Детекторы
реального времени ловят проблемы сразу, чтобы выполнялась SPEC-0001 G-1
(нет сигнала на известной проблеме). Детектор может только понизить статус
минуты до `DEGRADED` и перевести инструмент в `DEGRADED`. Окончательный
вердикт по минуте выносит сверка.

Реальный пример (2026-10-12): с 09:24 МСК процесс сотни тысяч раз писал в
лог «Could not contact DNS servers» (KI-19), стримы почти не открывались, с
14:18 МСК сделки не записывались вообще — и ни одного сигнала о деградации.
Ночью после перезапуска — 851 обрыв стрима из-за лимита соединений
(SPEC-0009), тоже без отметок.

Проверено 2026-10-13: сразу после подписки `SubscribeInfoRequest` сервер
присылает текущий торговый статус каждого инструмента с временем его смены
(`SECURITY_TRADING_STATUS_NORMAL_TRADING` и т. д.); лимита на число таких
подписок нет.

## Делаем / Не делаем

**Делаем:** детекторы ниже; статус `DEGRADED` по минутам с причинами;
состояние инструмента `OK` / `DEGRADED` и журнал переходов
(`DATA_DEGRADED` / `DATA_RESTORED`); функции чтения для робота.

**Не делаем:** не исправляем данные (SPEC-0005); не останавливаем сбор;
не подавляем сигналы (это SPEC-0008, по данным отсюда); канал доставки
событий роботу — SPEC-0008 (пока события пишутся в лог и в таблицу).

## Модель

- **Минута** — интервал `[HH:MM:00, HH:MM+1:00)` UTC по инструменту.
  Минута без отметок — `PROVISIONAL`; минута хотя бы с одной причиной —
  `DEGRADED`.
- **Условие** — длящаяся проблема с причиной и моментом начала. Пока
  условие активно, инструмент в состоянии `DEGRADED`, и каждая минута от
  начала условия до его конца помечается этой причиной. Когда активных
  условий не остаётся — `OK`.
- **Разовая отметка** — проблема без длительности (ролловер, дилерская
  сделка): помечается одна минута, состояние не меняется.

## Детекторы

| Причина | Вид | Где | Условие | Пороги |
|---------|-----|-----|---------|--------|
| `stream_gap` | условие | хаб | Соединение не открыто: от старта процесса или обрыва до подтверждения новой подписки. При первом открытии начало — время последней сохранённой сделки инструмента, но не раньше начала суток UTC | — |
| `subscription_failed` | условие | хаб | Сервер не подтвердил подписку инструмента на сделки (до следующего открытия) | — |
| `stream_silence` | условие | хаб (сторож) | Торговый статус `NORMAL_TRADING`, а сделок нет дольше порога. Начало — последняя сделка, переход в `NORMAL_TRADING` или подтверждение подписки, что позже. Конец — первая сделка | порог = 20 × 95-й перцентиль интервалов между последними 200 сделками инструмента, в пределах [60 с, 900 с]; меньше 20 интервалов — 900 с |
| `latency` | условие | хаб (сторож) | Медиана `время получения − время сделки` за 30 с > 5 с; конец — < 3 с (гистерезис). Для всех инструментов | 5 с / 3 с |
| `backlog` | условие | коллектор | Очередь больше 50% ёмкости; конец — меньше 10% | 5 000 / 1 000 |
| `write_failure` | условие + минуты пакета | коллектор | Ошибка записи пакета: минуты сделок потерянного пакета помечаются; условие до следующей успешной записи | — |
| `unknown_direction` | разовая | коллектор | В закрывшейся минуте при статусе `NORMAL_TRADING` ≥ 20 сделок и доля без стороны > 50% (аукционы не считаются: у них свой статус) | 20 / 50% |
| `contract_roll` | разовая | хаб | При переподключении с резолюцией у непрерывного фьючерса сменился FIGI | — |
| `dealer_leak` | разовая | коллектор | Пришла небиржевая сделка вопреки фильтру (SPEC-0002 G-3) | — |

Дополнительно сторож хаба переподключает соединение, если при идущих
торгах (хотя бы один инструмент в `NORMAL_TRADING`) от сервера не было ни
одного кадра 180 с: соединение считается мёртвым.

## Гарантии

- **G-1.** Каждая минута, затронутая сработавшим детектором, ДОЛЖНА получить
  статус `DEGRADED` до того, как по ней будет посчитан сигнал: длящиеся
  условия помечают минуты не реже раза в 5 с (сторож), хранилище обновляется
  при каждой записи консьюмера (не реже `flush_interval_sec`).
- **G-2.** Смена состояния инструмента ДОЛЖНА публиковаться событием
  `DATA_DEGRADED` (с причинами) или `DATA_RESTORED`: строка в журнале
  `quality_events` и строка лога с этим маркером.
- **G-3.** Детекторы НЕ ДОЛЖНЫ писать в БД из продюсера (инвариант A2):
  отметки и события копятся в памяти и сохраняются консьюмером; при ошибке
  записи остаются в памяти до следующей.
- **G-4.** Тишина при торговом статусе, отличном от `NORMAL_TRADING`
  (перерыв, аукцион, закрытие), НЕ ДОЛЖНА считаться деградацией.

## Поведение

**Сценарий: тишина при идущих торгах**
- Дано: SBER, статус `NORMAL_TRADING`, сделки в среднем раз в 0,2 с (порог — 60 с).
- Когда: 60 с нет сделок.
- Тогда: SBER → `DEGRADED(stream_silence)`, минуты с последней сделки помечаются; первая сделка → `DATA_RESTORED`.

**Сценарий: остановка торгов на бирже**
- Дано: торговый статус инструмента — `BREAK_IN_TRADING`.
- Когда: сделок нет.
- Тогда: деградации нет (G-4).

**Сценарий: обрыв соединения**
- Дано: соединение оборвалось в 11:00:10, открылось снова в 11:00:40.
- Тогда: у всех инструментов `DEGRADED(stream_gap)` с 11:00:10; минута 11:00 помечена; после подтверждения подписки — `DATA_RESTORED`.

## Данные и контракты

SQLite инструмента (через `MarketDataRepository`):

```sql
CREATE TABLE degraded_minutes (
    minute  TEXT NOT NULL,   -- начало минуты, ISO UTC
    reason  TEXT NOT NULL,
    PRIMARY KEY (minute, reason)
);
CREATE TABLE quality_events (
    ts       TEXT NOT NULL,  -- момент перехода, ISO UTC
    state    TEXT NOT NULL,  -- DEGRADED | OK
    reasons  TEXT NOT NULL   -- активные причины через запятую
);
```

Чтение для робота (`reader.py`): `get_degraded_minutes(repo, start, end)` —
минуты `DEGRADED` с причинами; `get_data_state(repo)` — текущее состояние
инструмента (последняя строка журнала).

Подписка на торговые статусы (`SubscribeInfoRequest`) — в том же соединении
(SPEC-0009), отдельным сообщением.

## Наблюдаемость

- Лог: `DATA_DEGRADED X: причины` (WARNING), `DATA_RESTORED X` (INFO),
  `Подписка на торговые статусы подтверждена: N из M`, `Стрим сделок мёртв: нет кадров N с — переподключение`.

## Журнал решений

- **2026-10-12** — Детекторы только понижают статус; вердикт — за сверкой.
- **2026-10-13** — Живая проверка нашла ложное срабатывание: тишина отсчитывалась от смены торгового статуса (07:00 МСК), и 12 малоликвидных инструментов сразу после старта стали `DEGRADED`. Теперь отсчёт — не раньше подтверждения подписки (время до неё покрыто `stream_gap`).
- **2026-10-13** — Согласовано к реализации. Порог тишины адаптивный (по интервалам между сделками инструмента), а не по истории: история до SPEC-0006 ненадёжна. Хранятся только минуты с отметками (разреженно); статусы сверки (`VERIFIED` и т. д.) добавит SPEC-0005.
