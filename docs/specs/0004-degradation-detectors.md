# SPEC-0004: Детекторы деградации данных

**Статус:** Черновик · **Обновлено:** 2026-10-12 · **Зависит от:** SPEC-0001

## Зачем

Сверка с ISS (SPEC-0005) выносит вердикт через 15–20 минут. Детекторы
реального времени ловят проблемы сразу, чтобы выполнялась SPEC-0001 G-1
(нет сигнала на известной проблеме). Детектор может только понизить статус
минуты до `DEGRADED` и перевести инструмент в `DEGRADED`. Окончательный
вердикт по минуте выносит сверка.

Реальный пример (2026-10-12): с 09:24 МСК процесс сотни тысяч раз писал в
лог «Could not contact DNS servers» (KI-19), стримы почти не открывались, с
14:18 МСК сделки не записывались вообще — и ни одного сигнала о деградации.
Ночью после перезапуска — 851 обрыв стрима из-за лимита соединений
(SPEC-0009), тоже без отметок.

## Делаем / Не делаем

**Делаем:** детекторы ниже, события `DATA_DEGRADED` / `DATA_RESTORED`, статусы минут.

**Не делаем:** не исправляем данные (это SPEC-0005); не останавливаем сбор.

## Детекторы

| Детектор | Условие (пороги — черновик) | Причина в событии |
|----------|------------------------------|-------------------|
| Разрыв потока | Стрим упал или переподключается: всё время от последней полученной сделки до подтверждения новой подписки | `stream_gap` |
| Тишина потока | Нет сделок дольше порога, при этом торговый статус инструмента — торги идут. Порог — от типичного интервала между сделками на это время дня | `stream_silence` |
| Отставание | `время получения − время сделки` > 5 с (медиана за 30 с) | `latency` |
| Очередь | Размер `asyncio.Queue` растёт N сбросов подряд или выше порога | `backlog` |
| Сбой записи | Ошибка пакетной записи консьюмера | `write_failure` |
| Доля UNKNOWN | Доля сделок без стороны вне аукционов выше нормы | `unknown_direction` |
| Ролловер | Непрерывный фьючерс переключился на новый контракт | `contract_roll` |
| Аномалия источника | Пришла дилерская сделка вопреки фильтру (SPEC-0002 G-3) | `dealer_leak` |

## Гарантии

- **G-1.** Каждая минута, затронутая сработавшим детектором, ДОЛЖНА получить
  статус `DEGRADED` до того, как по ней будет посчитан сигнал.
- **G-2.** Смена состояния инструмента ДОЛЖНА публиковаться событием
  `DATA_DEGRADED` (с причиной) или `DATA_RESTORED`.
- **G-3.** Детекторы НЕ ДОЛЖНЫ писать в БД из продюсера (инвариант A2):
  статусы копятся в памяти и сохраняются консьюмером, как отметки дней.

## Поведение

**Сценарий: тишина при идущих торгах**
- Дано: SBER, 11:00 МСК, торговый статус — торги идут.
- Когда: 30 с нет сделок при типичном интервале 0,2 с.
- Тогда: SBER → `DEGRADED(stream_silence)`, минуты помечаются, сигналы по SBER подавляются.

**Сценарий: остановка торгов на бирже**
- Дано: торговый статус инструмента — перерыв.
- Когда: сделок нет.
- Тогда: деградации нет: тишина объясняется рынком.

## Данные и контракты

- Подписка на торговый статус (`SubscribeInfoRequest`) в том же стриме.
- Таблица статусов минут (общая с SPEC-0005/0006) — через `MarketDataRepository`.
