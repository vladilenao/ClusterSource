# SPEC-0005: Сверка с ISS и дозаливка

**Статус:** Готово (ждёт перезапуска сервиса) · **Обновлено:** 2026-10-13 · **Зависит от:** SPEC-0002, 0003, 0004, 0009

## Зачем

Стрим T-Invest терял сделки молча (SPEC-0001: от 1 до 97% за день). Лента
Мосбиржи (SPEC-0003) с задержкой 15 минут позволяет проверить каждую минуту и
исправить её, не дожидаясь ночного архива.

Почему дозаливаем, а не только помечаем (решение 2026-10-12): при потерях
5–40% в обычный день вариант «только помечать» оставлял бы робота без
сигналов большую часть времени; ISS — сама биржа, источник авторитетнее
брокера; ночью день всё равно заменяется архивом с микросекундами (SPEC-0006).

### Исследование 2026-10-13 (стрим против ленты ISS, 56 инструментов)

Ключ сравнения: секунда UTC (у стрима — время, округлённое вниз до секунды;
у ISS — `TRADETIME` → UTC), цена, количество, сторона.

| Окно (МСК) | Стрим | ISS | Секунд совпало точно | «Лишних» у нас |
|-----------|-------|-----|----------------------|----------------|
| 07:00–07:45 — до SPEC-0009, соединения сбрасывались | 59 305 | 97 539 | 15 708 / 24 540 (64%) | 0 |
| 07:52–08:07 — одно соединение (SPEC-0009) | 20 474 | 20 474 | 6 217 / 6 217 (100%) | 0 |
| 08:24–08:28 — текущий процесс | 6 399 | 6 399 | 1 960 / 1 960 (100%) | 0 |

Выводы:
- сдвиг времени нулевой: секунда сделки в стриме совпадает с `TRADETIME`
  (на 49 тыс. пар — 27 совпадений со сдвигом ±1–2 с, это повторяющиеся
  одинаковые сделки, а не сдвиг часов);
- стороны и единицы объёма совпадают (у бумаг с лотом > 1 тоже);
- при потерях недостающие секунды обычно отсутствуют у нас целиком
  (8 813 из 8 832);
- «лишних» сделок у нас нет; ловушка одна — сверять можно только то, что
  ISS уже отдал (граница — последняя сделка ленты, а не «сейчас − 15 мин»).

Отдельно: проверка пропусков числового `trade_id` (`collector._flag_gap`)
несовместима с номерами биржи (на фондовом рынке `TRADENO` общий для всех
бумаг, на FORTS не монотонен) и удаляется (G-4).

## Делаем / Не делаем

**Делаем:**
- фоновую задачу сверки: каждую минуту по каждому инструменту сверяются
  целые минуты от курсора до границы ленты ISS;
- `VERIFIED` — совпало, сделкам стрима проставляется `TRADENO`;
- `REPAIRED` — несовпавшие секунды заменяются сделками ISS (`origin = iss`);
- `GAP` — сверить нельзя (подробности ниже), данные не трогаются;
- у тиков — колонки `origin` (`stream` / `iss` / `archive`) и
  `exchange_trade_no`;
- функции чтения вердиктов для робота;
- удаление проверки пропусков числового `trade_id`.

**Не делаем:**
- итоги проверки сигналов (`SIGNAL_CONFIRMED` / `SIGNAL_REVOKED`) — SPEC-0008:
  сигналов пока нет, здесь — данные для них;
- не трогаем прошедшие дни из архива (`FINAL` — SPEC-0006): сверяется
  горячее хранилище.

## Правила сверки

1. **Сопоставление инструмента:** акции — `SECID = id`, режим `TQBR`;
   фьючерсы — `SECID` = тикер активного контракта из резолюции хаба
   (для непрерывных — `nearest_contract`), режим `RFUD`.
2. **Граница:** минута сверяется, когда она целиком раньше границы рынка =
   время последней сделки текущей ленты ISS рынка − 2 с, и раньше
   «сейчас − 16 мин» (консьюмер дописал её тики). Если у инструмента активно
   условие `backlog` или `write_failure` — сверка инструмента ждёт.
3. **Посекундно** сравниваются мультимножества (цена до 1e-6, количество, сторона):
   - **совпали** — секунда `VERIFIED`, сделкам стрима проставляются `TRADENO`;
   - **у нас меньше** (наши сделки — подмножество биржевых) — сделки стрима за
     секунду заменяются сделками ISS с `origin = iss`, `trade_id = x{TRADENO}`,
     временем — началом секунды;
   - **у нас есть сделка, которой нет у ISS** — данные не трогаются, минута `GAP`
     (`extra_trades`): «лишних» сделок в исследовании не было ни одной, их
     появление значит неполное покрытие ISS или ошибку, и удалять наши
     данные по слову ISS нельзя.
4. **Минута:** `REPAIRED`, если заменена хотя бы одна секунда, иначе `VERIFIED`.
   **`GAP`** без изменений данных, если:
   - у нас в минуте есть сделки, а у ISS нет ни одной (сомнение в покрытии ISS);
   - в какой-то секунде у нас есть сделка, которой нет у ISS (см. п. 3);
   - в большинстве несовпавших секунд расходится только сторона (маркер
     `ISS_DIRECTION_MISMATCH` — соглашение о стороне нарушено, дозаливка
     опасна).
5. Минута без сделок с обеих сторон вердикта не хранит: ниже курсора она
   считается `VERIFIED`.
6. Курсор инструмента (`recon_verified_until` в `meta`) — конец последней
   сверенной минуты. Первый запуск — с первой сделки текущей ленты ISS рынка.

## Гарантии

- **G-1.** Каждая минута с не-пустыми данными ДОЛЖНА получить вердикт
  `VERIFIED` / `REPAIRED` / `GAP`, как только ISS отдал её целиком (обычно
  15–17 мин после её окончания).
- **G-2.** Дозалитые сделки ДОЛЖНЫ иметь `origin = iss` и `exchange_trade_no`.
- **G-3.** Сверка НЕ ДОЛЖНА изменять дни с Parquet-файлом (архивные/`FINAL`) —
  только горячее хранилище текущей ленты.
- **G-4.** Проверка пропусков по числовому `trade_id` ДОЛЖНА быть удалена.
- **G-5.** Сверка минуты атомарна: проставление номеров, замена секунд,
  вердикт и курсор — одна транзакция.

## Данные и контракты

SQLite инструмента:

```sql
ALTER TABLE ticks_hot_store ADD COLUMN origin TEXT NOT NULL DEFAULT 'stream';
ALTER TABLE ticks_hot_store ADD COLUMN exchange_trade_no INTEGER;
CREATE TABLE minute_verdicts (
    minute     TEXT PRIMARY KEY,  -- начало минуты, ISO UTC
    status     TEXT NOT NULL,     -- VERIFIED | REPAIRED | GAP
    stream_n   INTEGER NOT NULL,  -- сделок стрима в минуте до сверки
    iss_n      INTEGER NOT NULL,  -- сделок ISS в минуте
    repaired   INTEGER NOT NULL,  -- заменено секунд
    detail     TEXT NOT NULL
);
```

Parquet получает те же колонки при архивации. Чтение (`reader.py`):
`get_minute_verdicts(repo, start, end)`, `get_verified_until(repo)`.

## Наблюдаемость

- `RECONCILE X: минут N (VERIFIED a, REPAIRED b, GAP c), дозалито K сделок, до T` (INFO; WARNING при REPAIRED/GAP).
- `ISS_DIRECTION_MISMATCH X минута M` (ERROR).
