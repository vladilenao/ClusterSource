# SPEC-0005: Сверка с ISS и дозаливка

**Статус:** Согласовано (принцип «дозаливать с пометкой»), детали — черновик · **Обновлено:** 2026-10-12 · **Зависит от:** SPEC-0002, 0003

## Зачем

Стрим T-Invest молча теряет сделки (SPEC-0001: от 1 до 97% за день).
Лента Мосбиржи (SPEC-0003) с задержкой 15 минут позволяет проверить каждую
минуту и исправить её, не дожидаясь ночного архива.

Почему дозаливаем, а не только помечаем (решение 2026-10-12):

| | Только помечать | Дозаливать с пометкой |
|---|---|---|
| Дневные индикаторы (CVD, профиль дня, VWAP, RVOL) после дыры | сломаны до конца дня, инструмент весь день без сигналов | корректны через 15–20 мин |
| Точность времени | микросекунды | у дозалитых сделок секунды; минутные кластеры это не затрагивает |
| Источник | — | сама биржа, авторитетнее брокера |
| Ночью | архив заменяет день | архив всё равно заменяет день с микросекундами (SPEC-0006) |

При потерях 5–40% в обычный день вариант «только помечать» оставлял бы
робота без сигналов большую часть времени.

Отдельно: текущая проверка пропусков `trade_id` (`collector.py`,
`_flag_gap`, `cur > prev + 1` по одному инструменту) несовместима с
номерами биржи. На фондовом рынке `TRADENO` общий для всех бумаг, у SBER
номера идут через ~35. На FORTS номера не монотонны. С настоящими номерами
она пометила бы `COMPROMISED` каждый день. Сейчас она не срабатывает только
потому, что в стриме нет номера.

## Делаем / Не делаем

**Делаем:**
- посекундную сверку стрима с ISS по инструментам ClusterSource;
- проставление `TRADENO` совпавшим сделкам;
- замену несовпавших секунд сделками биржи;
- вердикт по минутам и итоги проверки сигналов (SPEC-0001 G-2);
- замену числовой проверки пропусков `trade_id` этой сверкой.

**Не делаем:** не трогаем дни со статусом `FINAL`.

## Правила сверки

1. **Отбор ленты ISS для инструмента:**
   - акции — `SECID` = тикер и `BOARDID` = `TQBR`;
   - фьючерсы — `SECID` = контракт (для непрерывного — активный по
     `config.nearest_contract`), `OFFMARKETDEAL = 0`.
2. **Время ISS:** `TRADETIME` (МСК, секунды) → UTC. Сделки стрима
   группируются по той же секунде UTC. Допуск по смещению часов —
   определить экспериментом (открытый вопрос).
3. **По каждой секунде** сравниваются мультимножества (цена, количество, сторона):
   - **совпали** — сделки стрима остаются (точное время), им проставляется
     `TRADENO`, секунда `VERIFIED`;
   - **не совпали** (у нас меньше, больше или другие) — сделки стрима за эту
     секунду заменяются сделками ISS с `origin = iss`, секунда `REPAIRED`.
     Если у нас было больше, в метрику пишется `extra_trades`.
4. **Минута** получает худший статус своих секунд (`REPAIRED` хуже `VERIFIED`).
   Если данных ISS за минуту нет, а у нас есть, или ISS недоступен, минута
   получает `GAP`.
5. **Проверка соглашения о стороне:** на совпавших сделках `BUYSELL` ISS и
   `direction` стрима ДОЛЖНЫ совпадать. Систематическое расхождение — тревога
   и остановка дозаливки.
6. **Аукционы:** сделки с `PERIOD` аукциона открытия или закрытия помечаются.
   SPEC-0008 исключает их из «агрессивных».
7. **Итоги сигналов:** после вердикта по всем минутам окна сигнала выдаётся
   `SIGNAL_CONFIRMED` / `SIGNAL_REVOKED` по правилам SPEC-0001. Для `REPAIRED`
   окон сигнал пересчитывается на исправленных данных.
8. Детекторы, которым нужна точность меньше секунды (sweep, склейка крупной
   заявки по одинаковому времени), на `REPAIRED`-секундах не запускаются.

## Гарантии

- **G-1.** Каждая минута по каждому инструменту ДОЛЖНА получить вердикт
  `VERIFIED` / `REPAIRED` / `GAP` не позднее 20 минут после своего окончания,
  пока ISS доступен.
- **G-2.** Дозалитые сделки ДОЛЖНЫ быть помечены `origin = iss` и отличимы от сделок стрима.
- **G-3.** Сверка НЕ ДОЛЖНА изменять дни со статусом `FINAL`.
- **G-4.** Проверка пропусков по числовому `trade_id` ДОЛЖНА быть удалена:
  непрерывность номеров не является признаком полноты.

## Данные и контракты

- Тик: новые колонки `origin` (`stream` / `iss` / `archive`) и
  `exchange_trade_no` (может быть пустым). Миграция старых строк:
  `origin = stream` или `archive` по формату `trade_id`.
- `docs/contracts/schemas/tick.schema.json`, [03-data-model.md](../03-data-model.md).
- Таблица статусов минут — через `MarketDataRepository`.

## Наблюдаемость

- Метрики по инструменту и дню: доля `VERIFIED` / `REPAIRED` / `GAP` минут,
  число дозалитых сделок, число `extra_trades`, задержка вердикта.
- Лог при расхождении стороны с маркером `ISS_DIRECTION_MISMATCH`.
