# SPEC-0006: Ночной статус FINAL

**Статус:** Черновик · **Обновлено:** 2026-10-12 · **Зависит от:** SPEC-0002, 0005

## Зачем

SPEC-0001 G-3 требует считать пороги только по окончательным данным. Архив
T-Invest `history-trades` — точный источник: 2026-09-04 SBER после исключения
дилерских сделок совпал с итогами Мосбиржи сделка в сделку (120 760). Ночью
день заменяется архивом и сверяется с итогами биржи.

Отдельно, по эксплуатации (2026-10-12): в рабочей базе SBER нет таблицы
`days_to_refresh`, в горячем хранилище 40 дней вместо 7, Parquet есть только
за часть дней. Похоже, запущена сборка старее рабочей копии, а архиватор не
доходит до очистки. Перед внедрением нужно проверить, какая версия запущена.

## Правила

1. В ночное обслуживание каждый прошедший день, который ещё не `FINAL`,
   заменяется архивом (только `TRADE_SOURCE=EXCHANGE`, SPEC-0002).
2. Контроль по дневным итогам ISS
   (`/iss/history/engines/{engine}/markets/{market}/boards/{board}/securities/{secid}.json`,
   поля `NUMTRADES`, `VOLUME`):
   сравнение **по торговому дню** (`TRADEDATE`), а не по календарной дате.
   Сделки сессии выходного дня Мосбиржи относятся к следующему торговому дню.
3. Число сделок и объём совпали точно → все минуты дня `FINAL`. Не совпали
   → статус дня не меняется, тревога, повтор следующей ночью.

## Гарантии

- **G-1.** Статус `FINAL` ДОЛЖЕН ставиться только при точном совпадении числа
  сделок и объёма с итогами биржи за торговый день.
- **G-2.** Расчёт порогов (SPEC-0001 G-3) ДОЛЖЕН читать только `FINAL`-дни.
