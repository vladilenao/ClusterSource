# SPEC-0002: Только биржевые сделки

**Статус:** Готово · **Обновлено:** 2026-10-12 · **Зависит от:** —

## Зачем

T-Invest отдаёт два вида обезличенных сделок:

- **биржевые** (`TRADE_SOURCE_EXCHANGE`) — сделки Мосбиржи, включая её сессии
  выходного дня;
- **дилерские** (`TRADE_SOURCE_DEALER`) — внутренний рынок Т-Банка: клиенты
  торгуют с банком, когда биржа закрыта (дилерские сессии выходного дня,
  расширенные дилерские сессии `moex_extended`). Цену ставит дилер, объём
  отражает только клиентов Т-Банка. Для кластерного анализа это шум.

Факты:

- В официальном `marketdata.proto` у `SubscribeTradesRequest.trade_source` и
  `GetLastTradesRequest.trade_source` значение по умолчанию —
  **`TRADE_SOURCE_ALL`**. Подписка в `main.py` (`SubscribeTradesRequest` без
  `trade_source`) получает всё.
- Архив `history-trades` тоже содержит дилерские сделки. 2026-09-04 SBER
  загружен из архива: в нём 176 сделок в 02:00 МСК субботы, а без них ровно
  120 760 сделок, столько же, сколько в итогах Мосбиржи. Колонку `TRADE_SOURCE`
  `_history_rows` сейчас игнорирует.
- 12–13 сентября 2026 торгов выходного дня на Мосбирже не было, а в базе SBER
  за эти дни 5 735 и 4 854 сделки, то есть целиком дилерские.
- В базе SBER есть сделки в 23:00–03:00 UTC (02:00–06:00 МСК), когда биржа не торгует.

## Делаем / Не делаем

**Делаем:**
- фильтруем на источнике и при разборе, дилерские сделки не сохраняем вовсе;
- вычищаем уже сохранённые данные.

**Не делаем:**
- колонку `trade_source` в хранилище не заводим: сохраняются только биржевые
  сделки, поэтому колонка всегда равнялась бы `EXCHANGE`;
- не фильтруем по расписанию (часы, выходные): у Мосбиржи есть собственные
  сессии выходного дня, и фильтр по времени выбросил бы настоящие сделки.

## Гарантии

- **G-1.** В хранилище ClusterSource (SQLite, Parquet) ДОЛЖНЫ попадать только
  биржевые сделки.
- **G-2.** Фильтр ДОЛЖЕН стоять на каждом источнике:
  стрим — `SubscribeTradesRequest(trade_source=TRADE_SOURCE_EXCHANGE)`;
  `GetLastTrades` через REST — `trade_source=TRADE_SOURCE_EXCHANGE`;
  `GetLastTrades` через SDK — по полю `trade_source` каждой сделки (обёртка
  SDK 1.49 параметр не принимает, L-11);
  архив `history-trades` — строки с `TRADE_SOURCE ≠ EXCHANGE` отбрасываются при разборе.
  Правило отбора одно — `config.is_exchange_trade`: `EXCHANGE` и неуказанный
  источник принимаются, любое другое явное значение отбрасывается.
- **G-3.** Сделка с источником, отличным от биржевого, пришедшая вопреки
  фильтру, НЕ ДОЛЖНА сохраняться. Она учитывается как аномалия качества
  (счётчик и предупреждение в логе с маркером `DEALER_TRADE_DROPPED`).
- **G-4.** Ранее сохранённые данные ДОЛЖНЫ быть очищены: все прошедшие дни
  в хранилищах однократно отмечаются `dealer_cleanup` и перекачиваются из
  архива с фильтром G-2. Если архив подтвердил отсутствие биржевых сделок за
  день, день удаляется из хранилищ целиком.

## Поведение

**Сценарий: дилерская сессия ночью**
- Дано: 02:00 МСК субботы, Т-Банк проводит дилерские торги SBER.
- Когда: в архиве за этот день есть строки `TRADE_SOURCE=DEALER`.
- Тогда: они не попадают ни в SQLite, ни в Parquet.

**Сценарий: биржевая сессия выходного дня**
- Дано: суббота 09:50–19:00 МСК, торги выходного дня на Мосбирже.
- Когда: приходят сделки с `TRADE_SOURCE_EXCHANGE`.
- Тогда: сохраняются как обычные биржевые.

**Сценарий: защита от утечки**
- Дано: подписка с `TRADE_SOURCE_EXCHANGE`.
- Когда: в стриме пришла сделка с `trade_source = DEALER`.
- Тогда: сделка не кладётся в очередь, растёт счётчик, в логе `DEALER_TRADE_DROPPED`.

## Данные и контракты

- `docs/contracts/asyncapi/t-invest-market-data-stream.asyncapi.yaml`: в запросе
  подписки явно указан `trade_source: TRADE_SOURCE_EXCHANGE`.
- `docs/contracts/openapi/t-invest-rest.openapi.yaml`: то же для `GetLastTrades`.
- `docs/contracts/schemas/history-trade-record.schema.json`: описать значения `TRADE_SOURCE`.
- Схема тика не меняется.
- Чистка: отметка всех прошедших дней хранилищ причиной `dealer_cleanup` в
  `days_to_refresh` (`override=True`), флаг однократности в новой таблице
  `meta`. Отметки `dealer_cleanup` не ограничены окном `history_check_days`.
- Новый итог догрузки `BackfillResult.NO_EXCHANGE_TRADES`: архив опубликован,
  но все строки небиржевые. При перекачке день удаляется (`delete_day`).
  `NO_DATA` (404) по отметке `dealer_cleanup` для дня старше двух суток
  трактуется так же: архив за такой день уже точно опубликован.
- Чистка идёт фоновой задачей `main.run_dealer_cleanup` после запуска
  коллекторов: тысячи файлов при лимите архива ~28/мин заняли бы часы.
  Ограничитель темпа архива один на процесс; `maintenance_lock` не даёт
  перекачке дня пересечься с архиватором.

## Наблюдаемость

- Маркер лога `DEALER_TRADE_DROPPED` (инструмент, время, источник).
- Счётчик отброшенных строк архива с `TRADE_SOURCE ≠ EXCHANGE` по дням (INFO).

## Журнал решений

- **2026-10-12** — Дилерские сделки не сохраняем вообще, фильтр на источнике; колонку `trade_source` не заводим.
- **2026-10-12** — Сегодняшний день чисткой не отмечается: он уже отмечен `stream_gap` при открытии стрима и будет перекачан ночным обслуживанием.
- **2026-10-12** — Чистка выполняется в фоне после запуска коллекторов, а не в стартовом обслуживании, чтобы не задерживать сбор на часы.
- **2026-10-12** — День, по которому архив подтвердил отсутствие биржевых сделок (все строки дилерские, или 404 для дня старше двух суток по отметке чистки), удаляется целиком. Ложное удаление восстановимо из архива, а оставленные дилерские сделки нарушали бы G-1.
