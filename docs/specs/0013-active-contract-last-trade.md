# SPEC-0013: Активный контракт — по последнему дню торгов

**Статус:** Готово (ждёт перезапуска сервиса) · **Обновлено:** 2026-10-14 · **Зависит от:** SPEC-0006, 0009, 0012

## Зачем

Непрерывный фьючерс (`Si_CONTINUOUS` и др.) склеивается из контрактов: на
каждый день берётся «активный» контракт (`config.nearest_contract`). Правило
было «ближайшая `expiration_date` ≥ дня», но `expiration_date` в T-Invest — дата
исполнения, а торги идут только до `last_trade_date`, которая раньше на день
и больше:

| Контракт | `last_trade_date` | `expiration_date` |
|----------|-------------------|-------------------|
| SiU6, RIU6 | 17.09 (чт) | 18.09 (пт) |
| SVU6, GDU6 | 18.09 (пт) | 21.09 (пн) |
| BRU6 | 31.08 | 01.09 |
| BRV6 | 01.10 | 02.10 |
| NGU6 | 28.09 | 29.09 |

В дни между ними активным считался уже не торгующийся контракт:

- **архив** скачивался по нему (404), а разовая чистка SPEC-0002 12.10 даже
  удалила сохранённые данные таких дней («День Si_CONTINUOUS 2026-09-18 удалён»);
- **стрим** после ночного переподключения подписывался на него — день
  терялся и в реальном времени;
- **FINAL** (SPEC-0006) молчал: эталон брался по тому же контракту, 0 = 0.

Сверка с календарём ISS (SPEC-0012) 14.10 нашла 20 торговых дней без данных
у фьючерсов: 18 из них — эта ошибка (BR 01.09 и 02.10, NG 28.08 и 29.09,
Si/RI/MX/CR/Eu/GL/ED/RM 18.09, GD и SV 19–21.09), ещё 2 — CR и Eu 04.10
(воскресенье), причина не ясна. Впереди — 29.10 (NGV6) и 03.11 (BRX6).

## Делаем / Не делаем

**Делаем:**
- активный контракт — ближайший по `last_trade_date` ≥ дня; одно правило для
  стрима, догрузки, FINAL и сверки;
- ночную проверку «торговый день без данных» по календарю ISS: такие дни
  отмечаются для перекачки (`calendar_gap`) и пишутся в лог ERROR;
- перекачку найденных 20 дней тем же механизмом (при первом обслуживании).

**Не делаем:**
- отдельного режима ролловера (переход раньше последнего дня по
  ликвидности) — склейка остаётся «до последнего дня торгов».

## Правила

**Активный контракт** базового актива на день D — контракт с наименьшей
`last_trade_date` ≥ D. Нет `last_trade_date` в справочнике — берётся
`expiration_date` (прежнее поведение, с предупреждением в лог).

**Торговый день без данных.** В начале обслуживания для каждого инструмента
проверяются дни от первого сохранённого дня до вчера: если календарь ISS
(SPEC-0012) называет день торговым, а данных нет — день отмечается
`calendar_gap` (окном `history_check_days` не ограничен) и в лог пишется
`TRADING_DAY_MISSING`. Исключение — будний день, дневные итоги которого уже в
кэше ISS и у инструмента (у фьючерса — у всех контрактов актива) 0 сделок:
торгов действительно не было. Перекачка — тем же обслуживанием.

## Гарантии

- **G-1.** Активный контракт ДОЛЖЕН выбираться по последнему дню торгов: день
  после него НЕ ДОЛЖЕН относиться к истёкшему контракту.
- **G-2.** Торговый по календарю день без данных НЕ ДОЛЖЕН оставаться
  незамеченным: ERROR и отметка перекачки при каждом обслуживании, пока данных
  нет (кроме подтверждённых итогами дней без сделок).

## Данные и контракты

- `config.FuturesMeta.last_trade` — `last_trade_date` из справочника T-Invest
  (SDK `last_trade_date`, REST `lastTradeDate`).
- Отметка перекачки `calendar_gap` в `days_to_refresh`.

## Наблюдаемость

- `TRADING_DAY_MISSING X D: торговый день по календарю ISS, данных нет — отмечен для перекачки` (ERROR).
- `Непрерывный X -> активный контракт Y (последний день торгов D)` (INFO).

## Открытые вопросы

- [x] CR и Eu 04.10 (воскресенье) — настоящая дыра другой природы: архив отдал 2 023 и 105 сделок. Её скрывал допуск `ARCHIVE_CONSISTENT`: торговый день 05.10 (с выходными) у CR был согласован с итогами при недостаче 0,6%.

## Журнал решений

- **2026-10-14** — Склейка непрерывного фьючерса — по `last_trade_date`; пропуски торговых дней ищутся по календарю ISS при каждом обслуживании.
- **2026-10-14** — Перезапуск: найдено и перекачано 20 дней (18 — ошибка выбора контракта, 2 — CR/Eu 04.10); FINAL — 26 торговых дней `ARCHIVE_CONSISTENT`; после перекачки пропусков по календарю нет.
