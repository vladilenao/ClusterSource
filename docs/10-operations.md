# 10. Эксплуатация

## 10.1. Установка

```bash
python3.13 -m venv .venv && source .venv/bin/activate
pip install -e ".[sdk]"     # базовые зависимости + t-tech-investments
```

Если пакет `t-tech-investments` недоступен в PyPI вашей сети, скопируйте из
другого окружения в `.venv/lib/python3.13/site-packages/` каталоги `t_tech/`
и `t_tech_investments-*.dist-info`, а также зависимости `grpcio`,
`protobuf`, `iprotopy`, `sentry-sdk`, `urllib3`. Без SDK процесс
запускается, но стриминг не работает, а догрузка использует REST-фолбэки.

## 10.2. Запуск и остановка

```bash
cluster-source
```

| Действие | Как |
|----------|-----|
| Запуск | `cluster-source` или `python -m cluster_source.main` из каталога с конфигурацией |
| Остановка | `SIGINT` (Ctrl+C) или `SIGTERM`; процесс дописывает очередь тиков и завершается с кодом 0 |
| Проверка готовности | В логе есть `Подписка на сделки подтверждена: N из N` — стрим открывается через секунды после старта; перекачка дней, архивация и проверка FINAL идут после этого в фоне (SPEC-0011 G-5), до `Проверка FINAL завершена` |

На Windows обработчики сигналов не устанавливаются.

## 10.3. Файлы процесса

| Путь | Содержимое | Можно удалять |
|------|------------|---------------|
| `./cluster_source.log` | Лог (дописывается, без ротации) | да, при остановленном процессе |
| `{data_dir}/history/_sqlite/*.sqlite3` (+ `-wal`, `-shm`) | Горячее хранилище | нет, если данные не заархивированы |
| `{data_dir}/history/{storage}/*.parquet` | Холодное хранилище | да — день будет догружен, если входит в `history_check_days` и отсутствует в SQLite |
| `{data_dir}/history/_sqlite/_iss.sqlite3` | Лента Мосбиржи текущего дня и статусы полноты | **нет**: ISS отдаёт только текущий день |
| `{data_dir}/history/_iss/{market}/*.parquet` | Лента Мосбиржи прошедших дней | **нет**: восстановить нельзя |
| `{data_dir}/history/_iss_raw/` | Сырые файлы ленты ISS для ручного импорта (10.4.1); обычно отсутствует | после импорта (`raw_imported` в `iss_meta`) |

## 10.4. Регламент

Перезапуск по расписанию не нужен: обслуживание хранилища выполняется
процессом автоматически.

| Когда | Что выполняется |
|-------|-----------------|
| Старт процесса | Догрузка отсутствующих и перекачка отмеченных дней за `history_check_days` → архивация прошедших дней без Parquet → очистка SQLite старше `today − 7` → запуск стриминга; проверка FINAL прошедших торговых дней (SPEC-0006) — в фоне после запуска |
| Ежесуточно в `archiver.run_hour_utc:run_minute_utc` UTC (по умолчанию 00:05 UTC = 03:05 МСК) | То же обслуживание при работающих коллекторах (с проверкой FINAL после архивации), затем переподключение хаба для смены контрактов непрерывных фьючерсов |
| Постоянно, раз в `iss.poll_interval_sec` | Догонка ленты Мосбиржи; при смене дня в ISS — выгрузка прежней ленты в Parquet |
| Раз в час | Выгрузка лент, оставшихся в SQLite после падения; импорт сырых файлов этапа 1; проверка полноты торговых дней по итогам ISS |

Процесс должен работать постоянно, включая выходные: ISS отдаёт только
текущий день, и пропущенные номера сделок и ОИ по сделкам не восстановить.
На ноутбуке процесс не должен засыпать.

Объём ночной работы: около одной загрузки архива на инструмент в сутки
(перекачка дня, отмеченного `stream_gap`). При 58 инструментах и темпе
≤ 28 загрузок/мин — около 2–3 минут.

### 10.4.0. Mac не должен спать

Пока Mac спит, сбор стоит целиком (2026-10-13: сон 08:08–08:21 МСК, все
инструменты `DEGRADED(stream_gap)`). При `keep_awake: true` (по умолчанию)
процесс на macOS сам запускает `caffeinate -i -w <свой PID>`: сон по простою
запрещён, пока работает сбор, и разрешается сам после его остановки
([SPEC-0010](specs/0010-keep-awake.md)). В логе:
`Сон по простою запрещён, пока работает процесс (caffeinate, PID N)`.

Проверить, что запрет действует:

```bash
pmset -g assertions | grep caffeinate
```

Закрытая крышка ноутбука всё равно усыпит Mac (кроме режима с внешним
монитором и питанием, [L-13](12-known-issues.md#l-13)). Узнать, спал ли Mac:

```bash
pmset -g log | grep -E " (Sleep|Wake) "
```

Надёжное решение — запускать ClusterSource на машине, которая не спит
(мини-ПК, сервер, VPS).

### 10.4.1. Ручной импорт ленты ISS

Временный сборщик ленты (SPEC-0003, этап 1) отключён 2026-10-13: ленту
собирает сам сервис. Импорт сырых файлов остался: если положить файлы ленты
в формате ISS (CSV с заголовком колонок ISS, gzip) в
`{data_dir}/history/_iss_raw/{YYYY-MM-DD}/{shares|forts}*.csv.gz`, сервис
импортирует их при ближайшем обслуживании (раз в час) — только за дни, лента
которых в ISS уже сменилась; дубли отсекаются ключом уникальности.

## 10.5. Формат лога и ключевые сообщения

Формат: `%(asctime)s [%(levelname)s] %(name)s: %(message)s`, уровень INFO,
вывод в файл и stdout. `asctime` — локальное время хоста.

| Сообщение (фрагмент) | Уровень | Значение | Действие |
|----------------------|---------|----------|----------|
| `Не задан API-токен` | WARNING | Токен пуст или заглушка | Указать `TOKEN` в `config.local.yaml` |
| `Следующее ночное обслуживание через N с` | INFO | Планировщик ждёт | — |
| `Ночное обслуживание: старт` | INFO | Началось ежесуточное обслуживание | — |
| `Коллектор запущен для X (ключ хранения Y)` | INFO | Стрим открыт; день отмечен `stream_gap` | — |
| `Непрерывный X -> активный контракт Y` | INFO | Выбран контракт для склейки | Проверить, что контракт ожидаемый |
| `Инструмент X не найден — запуск коллектора отменён` | WARNING | Тикер отсутствует у провайдера | Исправить `id`/`type` |
| `Не удалось создать стрим для X … повтор через N с` | ERROR | Ошибка подключения | Сеть, токен, SDK |
| `Поток прерван для X (…); переподключение через N с` | WARNING | Разрыв, закрытие стрима или переподключение по запросу | Самовосстановление |
| `Ошибка флаша консьюмера` | ERROR | Пакет тиков не записан и потерян | Проверить диск/блокировки SQLite |
| `Загрузка архива истории KEY для X (D)` | INFO | Запрос к архиву | Для непрерывного фьючерса проверить `KEY` |
| `Архив истории ограничил лимит` | WARNING | HTTP 429 от архива | Самовосстановление |
| `Архив истории недоступен … лимит запросов исчерпан` | WARNING | День не догружен | Повторится при следующем обслуживании |
| `Архива истории нет для X за D` | INFO | 404 по всем ключам | Для отмеченного дня с данными — ждать публикации архива |
| `Невозможно догрузить X D: …` | ERROR | Не определены FIGI или ключ архива | Проверить справочник/резолюцию |
| `День X D перекачан из архива` | INFO | Отметка снята, данные заменены | — |
| `Отметка перекачки X за D (…) вышла за окно` | WARNING | День не удалось перекачать за `history_check_days` | При необходимости увеличить окно и перекачать вручную (10.6) |
| `АРХИВАЦИЯ НЕ УДАЛАСЬ` | ERROR | Parquet не записан | Проверить диск и права |
| `Очистка горячего хранилища X отменена: нет Parquet для дней …` | ERROR | Защита от потери данных сработала | Устранить причину ошибки архивации |
| `DATA_DEGRADED X: причины` | WARNING | Инструмент перешёл в `DEGRADED` (SPEC-0004) | По причине: `stream_gap`/`subscription_failed` — соединение; `stream_silence` — проверить торги и стрим; `latency` — сеть/часы; `backlog`/`write_failure` — диск и SQLite |
| `FINAL X: торговых дней N (FINAL a, MISMATCH b, UNVERIFIABLE c)` | INFO / WARNING | Ночной вердикт дней (SPEC-0006) | MISMATCH — день будет перекачан из архива (`final_mismatch`) |
| `DAY_NOT_FINAL X D: у нас n сделок / v, эталон m / w` | ERROR | День не совпал с эталоном биржи | Повтор следующей ночью после перекачки |
| `TAIL X D: хвост с ЧЧ:ММ МСК, минут m — совпал со свечами` | INFO | Хвост вечерней сессии сверен по минутным свечам ISS (SPEC-0011) | — |
| `TAIL_MISMATCH X D: минуты …` | ERROR | Хвост не совпал со свечами: минуты `GAP`, у фьючерсов день `MISMATCH` (перекачка) | Если повторяется после перекачки — разобрать `minute_verdicts.detail` (`candle_mismatch`) |
| `TAIL_UNAVAILABLE X D: свечей ISS нет` | WARNING | Свечи за день ещё недоступны; вердикта нет, повтор следующей ночью (3 суток) | Проверить доступность ISS |
| `Архив истории за D для X ещё не опубликован — отметка сохранена` | INFO | В 00:05 UTC архив за вчера обычно ещё не вышел | Перекачается при следующем обслуживании (или перезапуске) |
| `DAY_ARCHIVE_EXHAUSTED X D: перекачка из архива не изменила день` | ERROR | Перекачка не помогла: день остаётся `MISMATCH`, в нормы не идёт и больше не перекачивается (SPEC-0006 G-5); пишется один раз | Обычно сделки вне анонимной ленты сверх допуска (экспирация). Дыра в данных — перекачать вручную (10.6) |
| `RECONCILE X: минут N (VERIFIED a, REPAIRED b, GAP c), дозалито K сделок, до T` | INFO / WARNING | Сверка с лентой Мосбиржи (SPEC-0005); WARNING, если были REPAIRED или GAP | Много REPAIRED — стрим теряет сделки (см. `DATA_DEGRADED`); GAP — разобрать `minute_verdicts.detail` |
| `ISS_DIRECTION_MISMATCH X минута M` | ERROR | Стороны сделок стрима и ISS расходятся — дозаливка остановлена для минуты | Проверить маппинг направления |
| `DATA_RESTORED X` | INFO | Причины деградации устранены | — |
| `Стрим сделок мёртв: нет кадров N с` | ERROR | При идущих торгах сервер молчит — переподключение | Самовосстановление |
| `Подписка на торговые статусы подтверждена: N из M` | INFO | Статусы для детектора тишины | N < M — у части инструментов тишина не контролируется |
| `ISS X D: +N сделок, курсор K` | INFO | Лента Мосбиржи догнана | — |
| `ISS X: новая лента за D` | INFO | ISS перешёл на новый день, прежний выгружен в Parquet | — |
| `ISS_FEED_INCOMPLETE` | ERROR | Лента сменилась до догонки: номера сделок и ОИ за остаток дня потеряны | Проверить, что процесс работал и не спал |
| `ISS_DAY_VERIFIED` | INFO | Лента торгового дня полна до среза: по бумагам не больше итогов, недостача ≤ 2% (хвост сессии и сделки вне анонимной ленты), срез не раньше 23:30 МСК (SPEC-0011) | — |
| `ISS_DAY_INCOMPLETE` | ERROR | Лента больше итогов, недостача > 2% или лента обрывается раньше 23:30 МСК | Разобрать по `iss_day_status.detail`; проверить, что процесс работал вечером |
| `ISS: ошибка запроса … повтор` | WARNING | Сеть или ISS | Самовосстановление |
| `Ошибка автозагрузки` / `Ошибка сверки архиватора` | ERROR | Этап обслуживания завершился исключением | Разобрать трассировку; стриминг продолжит работу |

## 10.6. Перекачка дня вручную

Отметьте день для перекачки — данные дня будут заменены официальным
архивом при ближайшем обслуживании (при старте или ночью). День должен
входить в окно `history_check_days`.

```bash
python -c "from cluster_source.config import AppConfig; from cluster_source.database import MarketDataRepository as R; c = AppConfig.from_yaml('config.local.yaml'); i = next(x for x in c.instruments if x.storage_name == 'SBER'); R(c.storage_root, i).mark_days_for_refresh(['2026-10-09'], 'manual')"
```

Подставьте свой файл конфигурации, ключ хранения и дату. Отметку можно
ставить при работающем процессе.

## 10.7. Диагностика

| Симптом | Вероятная причина | Проверка / решение |
|---------|-------------------|--------------------|
| `unable to get local issuer certificate` | Нет `truststore` / системного CA | `pip install truststore`; не отключать проверку TLS |
| gRPC: `Could not contact DNS servers` при работающем HTTP | Резолвер c-ares gRPC не может обратиться к DNS (песочница, VPN с fake-ip) | `main.py` сам задаёт `GRPC_DNS_RESOLVER=native` ([KI-19](12-known-issues.md#ki-19)); если ошибка остаётся — проверить, не переопределена ли переменная в окружении |
| Массово `RST_STREAM with error code 8`, стримы открываются и сразу обрываются | Превышен лимит одновременных стрим-соединений T-Invest (16 на грейдах 1–4) | [SPEC-0009](specs/0009-single-market-data-stream.md) |
| `t-tech-investments не установлен` | Нет SDK | См. 10.1 |
| `database is locked` | Долгая транзакция внешнего читателя | Читатели должны использовать WAL и короткие транзакции |
| Отметки `days_to_refresh` не снимаются | Архив за день ещё не опубликован или ключ архива неверен | Проверить строки `Загрузка архива истории` в логе ([L-01](12-known-issues.md#l-01)) |
| Остановка процесса занимает несколько секунд | Консьюмер замечает остановку за `flush_interval_sec` | Ожидаемо ([L-07](12-known-issues.md#l-07)) |
